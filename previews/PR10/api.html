API Reference ​

This page documents the public API of Parking. All symbols listed here are exported from the package.

Vehicle and geometry ​

Parking.Vehicle Type
julia
Vehicle(Lf, Lr, width, wheelbase, max_steer)

Vehicle geometry and constraints.

  • Lf: distance from rear axle to front bumper

  • Lr: distance from rear axle to rear bumper

  • width: vehicle width

  • wheelbase: distance between front and rear axles

  • max_steer: maximum front-wheel steering angle (radians)

source
Parking.Pose Type
julia
Pose(x, y, θ)

The vehicle configuration (pose) in the environment.

  • x, y: rear-axle center coordinates

  • θ: heading angle (radians, 0 means aligned with the +x direction)

source
Parking.Rectangle Type
julia
Rectangle(cx, cy, L, W, θ)

An oriented rectangle (used for obstacles and bounds).

  • cx, cy: center

  • L: full length along the local x-axis (direction θ)

  • W: full width along the local y-axis

  • θ: orientation (radians)

source
Parking.corners Function
julia
corners(r::Rectangle)

Return the world coordinates of the rectangle's four corners (front-left, front-right, rear-right, rear-left).

source
Parking.footprint Function
julia
footprint(vehicle, pose)

Return the world coordinates of the vehicle's four corners (a convex quadrilateral), in the order: front-left, front-right, rear-right, rear-left. Used for collision detection and drawing.

source
Parking.rear_axle_pose Function
julia
rear_axle_pose(vehicle, x, y, θ) -> Pose

Convert a "geometric-center pose" into the internally used "rear-axle-center pose". The reference point is the rear axle; the geometric center is offset forward along the heading by (Lf - Lr)/2 relative to the rear axle.

source

Environment and parking spots ​

Parking.ParkingSpot Type
julia
ParkingSpot(center, length, width)

The target parking spot. center is the spot's center pose (which determines the final position and orientation after parking); length/width are the spot's full length and width.

source
Parking.spot_corners Function
julia
spot_corners(spot::ParkingSpot)

Return the world coordinates of the parking spot's four corners.

source
Parking.Environment Type
julia
Environment(bounds, obstacles, spot)

The full simulation environment.

  • bounds: axis-aligned drivable rectangle (vehicle footprint must not exceed it)

  • obstacles: list of obstacle rectangles (parked cars, curb walls, etc.)

  • spot: the target parking spot

source
Parking.inflate_rect Function
julia
inflate_rect(r::Rectangle, d) -> Rectangle

Expand the rectangle outward by d meters on every side (length and width each increase by 2d). Used to add a collision safety margin.

source
Parking.with_clearance Function
julia
with_clearance(env, clearance) -> Environment

Return a "planning" environment in which all obstacles are inflated by clearance and the drivable bounds are shrunk by clearance. Planning in this environment keeps the vehicle away from edges and prevents scraping; drawing still uses the original env.

source
Parking.build_lot Function
julia
build_lot(; length=20.0, width=10.0) -> (Environment, Vehicle)

Build a simple open-lot scenario. The lot is an axis-aligned rectangle with no obstacles; the vehicle is a typical sedan (length 4.5m, width 1.8m, wheelbase 2.7m). Mainly for verifying basic functionality.

source

Collision checking ​

Parking.is_collision Function
julia
is_collision(vehicle, pose, env) -> Bool

Test whether the vehicle at the given pose collides with the bounds or any obstacle. A broad-phase prune is done first using the footprint's bounding box, and SAT narrow-phase checks are performed only on obstacles whose boxes overlap, which significantly speeds things up when there are many obstacles.

source
Parking.collision_reason Function
julia
collision_reason(vehicle, pose, env) -> Union{String, Nothing}

If the pose is in collision, return a reason string (out of bounds / overlaps obstacle i); otherwise return nothing. Used by the planner to give readable diagnostics when the start/goal is in collision.

source
Parking.path_clear Function
julia
path_clear(vehicle, path, env) -> Bool

Check that every pose along the entire path is collision-free (used to verify results).

source

Planning ​

Parking.PlanResult Type
julia
PlanResult

Planning result.

  • status: one of SUCCESS / NO_PATH_FOUND / START_IN_COLLISION / GOAL_IN_COLLISION

  • path: list of poses from start to goal (empty if failed)

  • reason: reason string for failure (empty if successful)

  • env_used: the (clearance-inflated) environment actually used for planning

  • expanded: number of nodes expanded (for diagnostics)

source
Parking.step_vehicle Function
julia
step_vehicle(vehicle, pose, v, δ, dt) -> Pose

Integrate the bicycle model for a single step.

  • v: velocity (m/s, signed: positive = forward, negative = reverse)

  • δ: front-wheel steering angle (radians, positive = left turn)

  • dt: time step (s)

Returns the new rear-axle-center pose. When the steering angle is nearly zero, we fall back to straight-line motion to avoid division by zero.

source
Parking.plan_park Function
julia
plan_park(vehicle, env, start; clearance=0.15,
          dx=0.3, dy=0.3, dθ=deg2rad(15),
          v=2.0, dt=0.5, n_steer=5, max_expand=200000) -> PlanResult

Plan a path for parking the vehicle into env.spot, starting from start. start is given in geometric-center coordinates and is converted to the rear-axle-center reference internally. The goal is the center pose of the parking spot. A safety clearance is added to all obstacles (and the bounds are shrunk) so the planned path keeps a margin from everything around it.

Returns PlanResult. On success, path is a list of rear-axle-center poses. On failure it reports the reason (start/goal in collision, or no path found).

source
Parking.plan_leave Function
julia
plan_leave(vehicle, env, start; clearance=0.15,
           dx=0.3, dy=0.3, dθ=deg2rad(15),
           v=2.0, dt=0.5, n_steer=5, max_expand=200000) -> PlanResult

Plan a path for the vehicle to leave the parking spot. start is the spot's center pose (rear-axle reference) and the goal is set to a "pulled-out" free pose in front of the spot. The rest is the same as plan_park.

The pull-out goal is placed 2.5 * vehicle.length ahead along the spot's heading, so the vehicle exits to a spot on the drive lane.

source

The planner reports its outcome through PlanResult. The status field is one of the PlanStatus values: SUCCESS, NO_PATH_FOUND, START_IN_COLLISION, or GOAL_IN_COLLISION. The reason field carries a human readable description of the outcome, e.g. "start pose is in collision (not in a valid free space)".

Simulation and refinement ​

Parking.simulate Function
julia
simulate(vehicle, traj; dt=traj.dt) -> Vector{Pose}

Re-simulate the trajectory with the bicycle model, returning the actually reached poses. dt can differ from the trajectory's sampling step (sub-sampling), and the result can be used to verify tracking error between the plan and the dynamics.

source
Parking.refine_path Function
julia
refine_path(vehicle, env, path; n_interp=4, v=2.0, dt=0.5, n_steer=5,
            n_inner=2, n_tries=8)

Refine the discrete grid path into a smooth, collision-free, continuous path. We walk along the path, replacing each "coarse" arc between adjacent poses with a finer local search (finer steering/velocity/time samples), and stitch the results into a higher-resolution trajectory. The refined path still satisfies collision constraints (checked against the original env, i.e. without extra clearance).

Approach:

  1. Interpolate n_interp intermediate poses between adjacent grid poses.

  2. For each interpolated segment, search locally for a feasible finer arc (smaller dt and denser steering/velocity samples) and concatenate.

Returns the refined Vector{Pose}.

source
Parking.Trajectory Type
julia
Trajectory(poses, dt)

A trajectory sampled at a fixed time step.

  • poses: list of rear-axle-center poses (the path)

  • dt: time step between adjacent poses (s)

The total duration is dt * (length(poses) - 1).

source
Parking.duration Function
julia
duration(traj) -> Float64

Total duration of the trajectory (s).

source
Parking.trajectory Function
julia
trajectory(path; dt=0.5) -> Trajectory

Build a Trajectory from a planned path, with a default time step of 0.5 s.

source

Visualization ​

Drawing and animation are provided by optional package extensions, so the core package stays lightweight:

  • ParkingPlots - loaded automatically when Plots is in scope. Provides plot_scene, plot_pose!, plot_path!, and animate_parking.

  • ParkingMakie - loaded automatically when Makie, Bonito, and WGLMakie are in scope. Provides plot_scene!, makie_scene, the interactive designer, and also implements plot_pose! / plot_path! for a Makie Axis.

plot_pose! and plot_path! are backend-agnostic: their target is a Plots.Plot (Plots backend) or a Makie Axis (Makie backend). Load the matching backend before calling any of these, e.g. using Parking, Plots or using Parking, Makie, Bonito, WGLMakie.

plot_scene(env, vehicle; kwargs...)

Render the static parking scene with Plots.jl. Provided by the ParkingPlots extension (load Plots.jl first).

source

source

julia
animate_parking(env, vehicle, path; kwargs...)

Animate the vehicle along path and export a GIF. Provided by the ParkingPlots extension.
